# B站UP主开播监测插件

一个用于监测 B 站 UP 主开播状态的 AstrBot 插件。当订阅的 UP 主开播或下播时，插件会自动推送通知（可附带直播间封面图）。

- 📦 **版本**：1.2.1
- 🧩 **插件名**：`astrbot_plugin_bilibiliobs`（`bili_live_notice`）
- 🔧 **要求**：AstrBot `>= 4.0.0`

---

## ✨ 功能特性

| 功能 | 说明 |
|------|------|
| 🔍 **实时监测** | 后台任务批量查询订阅 UP 主的直播状态 |
| 📢 **开播/关播通知** | 状态发生变化时立即推送，开播与关播可分别开关 |
| 🖼️ **封面图通知** | 开播通知自动附带直播间封面图（无需写在模板里） |
| 📣 **@全体成员** | 订阅时加 `at_all` 参数，该 UP 主开播时自动 @全体成员 |
| 👥 **会话隔离** | 每个群/会话的订阅列表相互独立，可重复订阅同一 UP 主 |
| ⏱️ **多会话错峰推送** | 同一 UP 主被多个群订阅时，通知按间隔依次送达，避免刷屏 |
| 📦 **批量操作** | 一次添加/移除多个 UP 主 |
| 📝 **自定义模板** | 开播/关播文案可自定义，支持 `{uname}`、`{title}`、`{room_id}` 占位符 |
| 🔐 **扫码续期 Cookie** | 管理员私聊 Bot 扫码登录，Cookie 自动写回配置（无需重启） |
| ⚠️ **Cookie 失效提醒** | API 返回 `-101` 时自动识别失效并私聊提醒管理员 |
| 🍪 **Cookie 支持** | 配置 B 站 Cookie 可获得更高 API 限额，降低被限流概率 |
| 🚦 **限流自适应** | 检测到 429 后自动放大检查间隔，恢复正常后逐步回落 |
| 🩹 **单 UID 退避** | 查询异常/无数据的 UID 按次数退避跳过，避免无效请求 |
| 💾 **数据持久化** | 订阅与通知开关自动保存，重启后自动恢复 |
| 🔄 **自动迁移** | 兼容旧路径与旧版全局订阅格式，启动时自动迁移 |

## 📦 安装

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

或手动安装：

```bash
pip install aiohttp>=3.8.0 qrcode>=7.4.0 Pillow>=10.0.0
```

> `qrcode` 与 `Pillow` 仅在**管理员扫码续期 Cookie** 时使用；未安装时插件其余功能不受影响，扫码命令会提示失败。

### 2. 安装插件

把插件目录放到 AstrBot 的插件目录下（`data/plugins/astrbot_plugin_bilibiliobs/`），然后在 WebUI 中重载插件。

## 🎮 指令一览

所有指令都需要按 AstrBot 的唤醒方式触发（群聊中 @机器人 或使用唤醒前缀 `/`）。

### 订阅管理

| 指令 | 说明 |
|------|------|
| `/添加订阅 <UID> [at_all]` | 添加一个 UP 主到当前会话订阅列表 |
| `/批量添加订阅 <UID1> <UID2> ... [at_all]` | 批量添加多个 UP 主 |
| `/移除订阅 <UID>` | 从当前会话移除订阅 |
| `/批量移除订阅 <UID1> <UID2> ...` | 批量移除多个 UP 主 |
| `/订阅列表` | 查看当前会话的订阅列表与实时直播状态 |
| `/检查直播 <UID>` | 手动查询指定 UP 主当前直播状态（开播时附封面图） |

示例：

```
/添加订阅 123456
/添加订阅 123456 at_all
/批量添加订阅 123456 789012 345678
/批量移除订阅 123456 789012
```

### 通知开关（全局生效并持久化）

| 指令 | 说明 |
|------|------|
| `/开启通知` | 开启开播 + 关播通知 |
| `/关闭通知` | 关闭全部通知 |
| `/开启关播通知` | 仅开启关播通知 |
| `/关闭关播通知` | 仅关闭关播通知 |

### 状态与帮助

| 指令 | 说明 |
|------|------|
| `/插件状态` | 查看 HTTP 会话、监测任务、订阅总数、订阅会话数、配置文件状态 |
| `/订阅帮助` | 查看全部指令与当前运行参数 |

### Cookie 扫码续期（管理员私聊）

私聊 Bot 发送以下任意一条即可获取登录二维码：

```
更新cookie
更新b站cookie
b站登录
bilibili登录
扫码登录
```

扫码登录流程：

1. **记录管理员**：管理员首次私聊 Bot 发送任意消息，系统会自动记录该会话（用于推送 Cookie 失效提醒）
2. **发起登录**：私聊发送 `更新cookie`（或其它等价命令）
3. **获取二维码**：Bot 返回登录二维码图片（有效期 3 分钟），并附带可点击的链接
4. **扫码确认**：使用哔哩哔哩手机客户端扫码并确认登录
5. **自动更新**：Bot 提示 “B站扫码登录成功，Cookie已自动更新”，Cookie 已写回插件配置，无需重启

> 同一时间只允许一轮扫码登录；二维码过期或超时会私聊提示重新发起。

## ⚙️ 配置项

在 AstrBot WebUI 的插件配置页可修改以下选项：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `check_interval` | int | `60` | 直播状态检查间隔（秒），建议 30–300 |
| `stagger_interval` | int | `15` | 同一 UP 主多会话订阅时的错峰推送间隔（秒），`0` 表示不延迟 |
| `max_monitors` | int | `50` | 每个会话最多订阅的 UP 主数量 |
| `enable_notifications` | bool | `true` | 是否发送开播通知（也可用 `/开启通知` 切换） |
| `enable_end_notifications` | bool | `true` | 是否发送关播通知 |
| `bilibili_cookie` | string | `""` | B 站 Cookie，留空为匿名请求；可扫码自动填写 |
| `admin_umo` | string | `""` | 管理员会话 ID，自动维护，用于推送 Cookie 失效提醒 |
| `live_notify_template` | string | 见下 | 开播通知模板 |
| `end_notify_template` | string | 见下 | 关播通知模板 |

默认模板：

```
🔴 {uname} 开播啦！
📺 直播标题: {title}
🔗 直播间: https://live.bilibili.com/{room_id}
```

```
⚫ {uname} 已结束直播
```

### 模板占位符

| 占位符 | 说明 |
|--------|------|
| `{uname}` | UP 主名称 |
| `{title}` | 直播标题（关播通知中为空） |
| `{room_id}` | 直播间号 |

说明：

- 封面图会自动附带，模板中无需（也不应）写 `{cover}`
- 换行可直接在配置框内回车，也可以输入字面 `\n`，插件会自动转换为真实换行
- 订阅了且带 `at_all` 的 UP 主开播时，消息会先 @全体成员

## 🧠 工作原理

1. **批量查询**：调用 B 站官方接口 `https://api.live.bilibili.com/room/v1/Room/get_status_info_by_uids`，一次请求获取所有订阅 UP 主的状态
2. **状态对比**：把本轮结果与上一轮缓存对比，得出「开播」/「关播」事件
3. **先更新缓存再派发**：先写入缓存再发送通知，避免同一轮重复触发
4. **错峰派发**：同一 UP 主被多个会话订阅时，按添加时间排序，按 `stagger_interval` 依次延迟发送
5. **限流与退避**：
   - 收到 429 时把检查间隔逐步放大（最多 300 秒），未限流时按 0.75 倍回落至配置值
   - 某个 UID 查询异常（无昵称且无直播间号）时按次数退避跳过
6. **Cookie 失效检测**：接口返回 `-101` 时触发 Cookie 校验，失效则私聊提醒管理员扫码续期
7. **会话隔离**：订阅列表按 `unified_msg_origin` 分组，各群互不影响

## ❓ 常见问题

**Q：添加订阅时提示「未找到UID为 xxx 的UP主」？**
A：请确认 UID 为纯数字且正确。获取方式：打开 UP 主主页，地址 `https://space.bilibili.com/123456` 中的 `123456` 即为 UID。

**Q：开播没有收到通知？**
A：依次检查 ① `/插件状态` 中「订阅检测任务」是否运行中；② `/订阅列表` 是否能看到该 UP 主；③ 通知开关是否开启；④ 日志中是否有 `请求频率限制` 提示（限流时插件会自动降速）。

**Q：通知里没有换行 / 显示了 `\n`？**
A：1.2.1 已自动清洗模板中的字面 `\n` 与 `\r\n`，请确认插件为最新版本。

**Q：Cookie 失效了怎么办？**
A：管理员私聊 Bot 发送 `更新cookie`，扫码后 Cookie 自动更新；也可在配置项 `bilibili_cookie` 中手动粘贴。

**Q：多个群都订阅了同一个 UP 主，会重复通知吗？**
A：每个会话都会收到，但会按 `stagger_interval` 错峰推送，避免瞬间刷屏；只想给一个群通知就只在那个群订阅。
